# Wireframes — PairEval M1

3 หน้าหลักที่ประกอบกันเป็น **user journey หลัก** ซึ่ง E2E ของ WS-04 จะเดินตาม

```
รายการงานที่ต้องประเมิน  →  เปรียบเทียบคู่  →  คะแนนของฉัน
      (US-07)                  (US-08)           (US-10)
```

ไฟล์ต้นฉบับ: [`paireval-m1.excalidraw.json`](paireval-m1.excalidraw.json)

> **หมายเหตุเรื่องรูปแบบไฟล์:** ไฟล์ JSON นี้เป็น element source ที่ใช้ render
> ไม่ใช่ไฟล์ `.excalidraw` มาตรฐานของ excalidraw.com (ซึ่งต้องมี `appState`, `seed`,
> `versionNonce` ครบทุก element) ถ้าต้องการ PNG หรือไฟล์ native ให้เปิด diagram
> แบบเต็มจอแล้ว export ออกมาวางไว้ในโฟลเดอร์นี้

## 1. หน้ารายการงานที่ต้องประเมิน — US-07

| ส่วน | รายละเอียด | locator ที่ E2E จะใช้ |
|---|---|---|
| Header | ชื่อระบบ + อีเมลผู้ใช้ที่ login | `getByRole('banner')` |
| หัวเรื่อง | "งานที่ต้องประเมิน" | `getByRole('heading', { level: 1 })` |
| ความคืบหน้า | แถบ + ตัวเลข `5 / 12 คู่` | `getByTestId('progress')` |
| Deadline | แสดงตาม **timezone ของ classroom** เสมอ | `getByTestId('deadline')` |
| รายการคู่ | การ์ดต่อ 1 คู่ · คู่ที่ทำแล้วเป็นสีเทา | `getByRole('list')` + `getByTestId('pair-list')` |

**AC ที่หน้านี้ต้องรองรับ**
- ทำไปแล้ว 5 จาก 12 → เห็นความคืบหน้าและรายการที่เหลือ
- ยังไม่ถึงเวลาเปิด → ไม่เห็นคู่ใด ๆ พร้อมข้อความบอกว่าเปิดเมื่อไร
- เลย deadline → กดเข้าคู่ไม่ได้ ตอบ `DEADLINE_PASSED`

## 2. หน้าเปรียบเทียบคู่ — US-08

หน้าที่สำคัญที่สุดของระบบ

| ส่วน | รายละเอียด | locator |
|---|---|---|
| ชื่อเกณฑ์ + น้ำหนัก | เช่น "ความคิดสร้างสรรค์ (30%)" | `getByTestId('criterion-name')` |
| ผลงาน A / B | สลับตำแหน่งซ้าย-ขวาแบบสุ่ม (D8) และบันทึกว่าใครเห็นแบบไหน | `getByTestId('work-left')` / `work-right` |
| ตัวเลือก 6 ระดับ | **ไม่มีตัวเลือกกลาง** (D1) | `getByRole('radio', { name })` |
| ปุ่มบันทึก | บันทึกแล้วไปคู่ถัดไป | `getByRole('button', { name: 'บันทึกและไปต่อ' })` |
| สถานะ autosave | บันทึกอัตโนมัติเมื่อหยุด 2 วินาที | `getByTestId('autosave-status')` |

> ตัวเลือกใช้ `getByRole('radio')` ไม่ใช่ `getByTestId` เพราะ role สะท้อนสิ่งที่ผู้ใช้เห็นจริง
> และทำให้ test จับปัญหา accessibility ให้ฟรีถ้าวันหนึ่งมีคนเปลี่ยนไปใช้ `<div onclick>`

## 3. หน้าคะแนนของฉัน — US-10

| ส่วน | รายละเอียด | locator |
|---|---|---|
| คะแนนกลุ่ม | ตัวเลขใหญ่ + เต็มกี่คะแนน | `getByTestId('group-score')` |
| รายละเอียดต่อเกณฑ์ | เกณฑ์ · น้ำหนัก · คะแนนที่ได้ | `getByTestId('score-breakdown')` |
| คะแนนรายบุคคล | **ซ่อนได้** ถ้ายังไม่ถึงเกณฑ์ k-anonymity (D7) พร้อมเหตุผล | `getByTestId('individual-score')` |
| ตัวคูณการมีส่วนร่วม | แยกจากคะแนนที่ได้รับโดยตั้งใจ (D5) | `getByTestId('participation')` |

**สถานะที่ต้องออกแบบเผื่อ** — หน้านี้มี 3 สถานะ ไม่ใช่สถานะเดียว

1. ยังไม่ `FINALIZED` → ไม่แสดงคะแนน บอกว่ายังไม่ประกาศผล
2. `FINALIZED` แต่ยังไม่ถึงเกณฑ์ k-anonymity → แสดงคะแนนกลุ่ม ซ่อนรายบุคคล พร้อมเหตุผล
3. `FINALIZED` และถึงเกณฑ์ → แสดงครบ

## สิ่งที่ wireframe นี้ตัดสินใจให้แล้ว

| เรื่อง | ตัดสินว่า | เพราะ |
|---|---|---|
| ปุ่ม "ข้ามคู่นี้" | **มี** แต่หมายถึงเลื่อนไปทำทีหลัง ไม่ใช่บันทึกว่า "เท่ากัน" | ถ้าเป็นทางออกให้ไม่ต้องตัดสินใจ จะขัด D1 ตรง ๆ |
| Deadline | แสดงตาม timezone ของ classroom เสมอ ไม่ใช่ของเครื่องผู้ใช้ | DR-05 เก็บ UTC แปลงตอนแสดง · ถ้าใช้ของเครื่องจะเห็นเวลาต่างกันคนละอย่าง |
| คะแนนรายบุคคลที่ถูกซ่อน | ต้องบอก**เหตุผล** ไม่ใช่แค่ไม่แสดง | ผู้ใช้ที่เห็นช่องว่างเปล่า ๆ จะคิดว่าระบบพัง แล้วไปถามอาจารย์ |
