# เทียบ Figma หน้าที่เหลือ และงานที่ต้องมี backend รองรับ

วันที่: 19 ตุลาคม 2026 · Branch: `codex/figma-frontend`

ต่อจากรอบก่อน (commit `83ca403`) ที่ยังค้าง: เทียบแบบละเอียดหน้าที่ยังไม่ได้วัด และงานที่ต้องให้ backend เก็บสถานะเพิ่ม

## วิธีวัด

- **Figma**: เปิดไฟล์แบบดูอย่างเดียว (ไม่ได้ล็อกอิน จึงไม่มีแผง inspect และส่งออกภาพไม่ได้) ซูม 50% / 100% แล้ววัดจากภาพหน้าจอ
  ภาพ 100% ของ pane = 1.152 px ต่อ 1 px ของแบบ — วัดเทียบกับความกว้างเฟรมที่รู้ค่า (1440 / 390) ทุกครั้ง
- **เว็บ**: ถ่ายด้วย Playwright + Edge headless ที่ 1440 px (เดสก์ท็อป) และ 390 px (มือถือ) จาก stack ในเครื่อง พร้อมข้อมูลเดโมที่สร้างผ่าน API
- ความแม่นยำโดยประมาณ ±4 px ที่ 100% และ ±8 px ที่ 50% · ไม่ได้ใช้ข้อมูล metadata ของ Figma เพราะไม่มีสิทธิ์ inspect
- Figma บล็อก headless browser จึงดึงภาพเฟรมอัตโนมัติไม่ได้ (ไม่ได้พยายามเลี่ยงการบล็อก)

## ทำตามแบบในรอบ "ทำให้เหมือน Figma" (เดิมเป็นจุดที่ต่างจากแบบ)

- **J24 ประกาศผลอัตโนมัติ**: ทำฟีเจอร์จริง — งานที่ยังไม่เคยประกาศ ระบบประกาศให้ 14 วันหลังกำหนดส่งสุดท้าย
  (`app/auto_finalize.py` ตรวจทุก 15 นาทีใน loop เดิม) · ข้ามงานที่มีรายการข้อมูลไม่พอ หรือยังไม่มีคำตอบเลย และ rollback ผลคำนวณ
  · ไม่ประกาศซ้ำหลังอาจารย์ reopen · audit ผู้กระทำ `system` · เตือนเจ้าของห้องล่วงหน้า 3 วันในกระดิ่ง ·
  แถบสถานะแสดงวันที่จาก `autoFinalizeAt`
  **ขัดกับ PRD G3 / §7.3** (อาจารย์เป็นผู้ประกาศ) — บันทึกใน [ADR-002](adr/ADR-002-auto-finalize.md) สถานะ Proposed รอทีมตัดสิน ·
  **ปิดไว้เป็นค่าเริ่มต้น** (`AUTO_FINALIZE_ENABLED=false`) จนกว่าทีมจะตัดสิน · เปิดเฉพาะใน E2E
- **J25 / J35 หน้าแยก**: `/classrooms/:id/assignments/:id/report` (`#group` `#individual` `#appeals`) ใช้แท็บร่วมกับ J26 / J28
  (`ReportTabs`) · แท็บคำร้องแสดงจำนวนที่รอตอบเมื่อประกาศผลแล้ว · ภาพหัวหน้าส่งออกจาก Figma (`334:1956`, `334:4859`) ·
  หน้าภาพรวมงาน (J31b) ไม่มีตารางคำร้องแล้ว ปุ่มพาไปหน้าแยก · `/scores` คืน `computedAt` สำหรับ "คำนวณล่าสุด"
- **J26 / J27**: ปุ่มย้ายไปท้ายการ์ด ทำกับ "คู่ที่เลือก" (กดชื่อคู่ที่ข้อมูลไม่พอ · เริ่มที่คู่แรก) · เมื่อไม่มีผู้มีสิทธิ์เหลือ
  เปิดกล่อง J27 "ส่งให้ประเมินเพิ่มไม่ได้" พร้อมทางเลือกประเมินเอง
- **J28 / J28c QS-06 และ QS-07**: คำนวณจริงแล้ว (`app/domain/quality.py`)
  - QS-07 ใช้ **Kendall's u** (ค่าความสอดคล้องสำหรับข้อมูลเปรียบเทียบเป็นคู่) แทน Kendall's W ที่ PRD เขียน
    เพราะ W ต้องให้ทุกคนจัดอันดับครบทุกชิ้น ซึ่งการสุ่มคู่ของระบบไม่มี — เกณฑ์ < 0.20 เท่าเดิม ·
    หน้าเว็บแสดง "u = …" ไม่ใช่ "W = …" ตามแบบ เพื่อไม่ให้ผู้อ่านเข้าใจผิด
  - QS-06 เทียบอัตราที่ผู้ประเมินให้เพื่อนร่วมกลุ่มแต่ละคนชนะ กับที่คนอื่นให้คนเดียวกัน (z > 2 เทียบทุกคู่ในงาน) ·
    ต้องมีส่วนต่างอย่างน้อย 10 ค่า (z ใช้ population SD มีเพดาน √(N−1) — น้อยกว่านี้รายงาน "ยังตรวจไม่ได้" ไม่ใช่ "ไม่พบ")
  - กล่อง J28c กราฟการกระจาย 6 ระดับต่อเกณฑ์ พร้อมค่าความสอดคล้อง
- **J13a**: ช่วงคะแนนเป็นกรอบเดียว "60% – 100%" (ข้างในยังเป็นสองช่องที่มีป้ายสำหรับโปรแกรมอ่านหน้าจอ)

## Backend ที่เพิ่ม

- `quality_review`, `export_log` (migration `022`)
- `POST /api/assignments/{id}/quality/{key}:reviewed`, `POST /api/assignments/{id}/reports:export`, `GET /api/assignments/{id}/exports`
- `/scores` คืน `criteria[]`, `overridden`, `formulaVersion` · coverage คืน `instructorCount`, `pendingCount`, `meanScoreA` · รายการงานคืน `finalizedAt`
- `app/auto_finalize.py` ประกาศผลอัตโนมัติ · รายการงานคืน `autoFinalizeAt` · `/scores` คืน `computedAt` · `/quality` คืน `criteria[]` (QS-07 + การกระจาย) และ `favoritismAssessed` · แจ้งเตือนเจ้าของห้องชนิด `auto_finalize`
- CORS expose `Content-Disposition` (เดิมไฟล์ที่ดาวน์โหลดจากหน้าเว็บได้ชื่อสำรอง)
