# รายการเปรียบเทียบ WEB ↔ Figma

วันที่สรุป: 19 ตุลาคม 2026 · Branch: `codex/figma-frontend`

เอกสารนี้รวบรวมรายการที่พบจากโค้ดเว็บปัจจุบัน ภาพเทียบที่ตรวจไว้ และการตรวจบนเว็บ/Figma ในบทสนทนานี้ ไม่ได้แก้ UI เพิ่มในรอบจัดทำเอกสาร

## ขอบเขตและวิธีอ่าน

- “WEB มี แต่ Figma ไม่มี” หมายถึงไม่พบใน **เฟรมอ้างอิงของหน้าที่เทียบ** ไม่ใช่ข้อยืนยันว่าไม่มีอยู่ที่ใดเลยในไฟล์ Figma ทั้งหมด
- “Figma มี แต่ WEB ไม่มี” รวมส่วนที่มีหน้ารองรับแล้ว แต่ยังขาดองค์ประกอบหรือการคำนวณนั้น โดยระบุขอบเขตในแต่ละรายการ
- Inventory มี 191 screen/state frames แต่ยังไม่ได้ตรวจภาพครบทุกเฟรม จึงไม่ใช่รายการครบถ้วนของทุก role/state
- ไม่ถือว่าชื่อผู้ใช้ ชื่อห้อง จำนวนรายการ วันที่ หรือคะแนนต่างจากข้อมูลตัวอย่างเป็นสิ่งที่ขาด/เกิน
- แยกการจัดวางที่ต่างออกจากฟีเจอร์ที่ขาด และแยกสิ่งที่ผู้ใช้สั่งปรับเองออกจากข้อผิดพลาด
- ภาพเทียบบางภาพถ่ายก่อนการแก้ล่าสุด หากขัดกับสถานะในหัวข้อ “แก้แล้ว” ให้ใช้สถานะล่าสุดในเอกสารนี้

## 3. ทั้งสองฝั่งมี แต่รูปแบบหรือการจัดวางต่างกัน

รายการนี้ไม่ควรถูกนับว่าเป็นฟีเจอร์ที่หายทั้งชุด

| ID | หน้า | Figma | WEB |
| --- | --- | --- | --- |
| D-01 | สร้างห้องเรียน · J03 | หัวข้อ “สร้างห้องเรียน”; เรียงชื่อ → รหัสวิชา → ภาคเรียน → เขตเวลา → โดเมน | หัวข้อ “สร้างห้องเรียนใหม่”; ชื่อ → เขตเวลา → รหัสวิชา/ภาคเรียนสองคอลัมน์ และยังไม่มีโดเมนตาม F-01 |
| D-02 | สร้างห้องเรียน · J03 | ปุ่มยกเลิกและสร้างห้องเรียนอยู่ด้านซ้ายของฟอร์ม | เว็บจัดปุ่มด้านขวา พร้อมเส้นคั่น |
| D-03 | ภาพรวมห้อง · J12 | ชุดปุ่ม “จัดการสมาชิก / สร้างงานประเมิน / ดูคะแนนของงาน” | เว็บใช้แท็บ “ภาพรวม / สมาชิก / งานประเมิน / คะแนน” และทางลัดบันทึกการตรวจสอบ |
| D-04 | จัดการสมาชิก/ผู้สอน | มีปุ่มเพิ่มผู้สอนเพื่อเข้าสู่ขั้นตอนเพิ่มผู้สอน | เว็บแสดงฟอร์มเพิ่มผู้สอนร่วม/TA ในหน้าเลย; ฟังก์ชันเพิ่มผู้สอนมีแล้ว |

## 4. ความต่างที่ผู้ใช้สั่งไว้

| รายการ | คำสั่ง/สถานะ |
| --- | --- |
| ปุ่ม “เข้าสู่ระบบด้วย Google” สีส้ม | ผู้ใช้สั่งให้ใช้รูปแบบนี้และเปิด Google login โดยตรง |
| กั้นหน้าภายในเมื่อยังไม่ login | ผู้ใช้สั่งให้ห้ามใช้หน้าอื่นก่อนเข้าสู่ระบบ |
| ภาพหน้าแรกและภาพห้องเรียนที่ AI ปรับความคมชัด | ผู้ใช้อนุญาตให้ใช้ภาพเดิมเป็นต้นแบบแล้ว generate ให้ชัด รายละเอียดบางส่วนต่างจาก Figma; เก็บภาพต้นฉบับไว้แล้ว |
| รหัสวิชาและภาคเรียนเป็นช่องบังคับ | ผู้ใช้สั่งเพิ่มเมื่อ 19 ตุลาคม 2026; ฟอร์ม frontend ตรวจค่าว่างและเว้นวรรคอย่างเดียวแล้ว; API เดิมยังรับสองค่านี้เป็น optional |

## 5. รายการที่แก้แล้ว ไม่ใช่งานค้าง

| รายการ | สถานะล่าสุด |
| --- | --- |
| ป้าย “พร้อมใช้งาน” บนการ์ดห้องเรียน | เอาออกแล้ว; เป็นคนละตัวกับป้ายสถานะ API ใน Footer ตาม W-01 |
| Dropdown แจ้งเตือนใต้กระดิ่ง | เพิ่มแล้ว ใช้ API จริง มี empty/loading/error และกดไปหน้าที่เกี่ยวข้อง; บัญชีที่ตรวจล่าสุดไม่มีรายการ จึงยังไม่ได้ยืนยันภาพ populated state เทียบ Figma |
| ไอคอนและข้อความในแบนเนอร์สร้างงานประเมินแรกไม่ตรงแนว | จัดกึ่งกลางแนวตั้งแล้ว ตรวจ DOM พบกึ่งกลางไอคอน ข้อความ และปุ่มตรงกัน |
| รหัสวิชาและภาคเรียนไม่บังคับกรอก | เพิ่ม required และตรวจเว้นวรรคแล้ว |

## 6. ต้องตรวจยืนยันเพิ่ม

- แถบตั้งค่าห้องเรียน 1–2–3: Figma มี Stepper master `91:389` จึงยังสรุปไม่ได้ว่าเป็นสิ่งที่ Figma ไม่มี ต้องตรวจว่ากำหนดให้ใช้ในหน้า/สถานะเดียวกับเว็บหรือไม่
- เมนูบัญชีและเนื้อหาที่กางจากปุ่มหน้าแรก: ต้องตรวจ prototype/เฟรมอื่นเพิ่มเติมก่อนตัดสินว่าควรลบทิ้ง
- รายละเอียด hover, loading, empty, error, ข้อความยาว และทุกบทบาทยังไม่ได้ตรวจครบทั้ง 191 เฟรม
- ข้อความแจ้งเตือนและรายงานที่ขึ้นกับข้อมูลจริง ต้องเทียบด้วยเงื่อนไขเดียวกัน ไม่สร้างค่าตัวอย่างแทนข้อมูลที่ไม่มี
