# ADR-007: เปิด login ทุกโดเมน และแยกนักศึกษา/ผู้สอนจากรูปแบบอีเมล

## Status

Accepted (ทีม) — **รอบันทึกการรับรองจากอาจารย์** ว่าเป็นส่วนขยายของ PRD §3 / FR-AUTH-02 ที่ยอมรับได้

## Date

2026-10-20

## Context

commit `219e16a` ตั้ง `ALLOWED_EMAIL_DOMAINS=""` ใน `render.yaml` และ `render.production.yaml`
และเพิ่ม [`app/domain/account.py`](../../backend/app/domain/account.py): ส่วนหน้า `@` เป็นตัวเลขล้วน = นักศึกษา
แบบอื่น = ผู้สอน (สร้างห้องได้) · `POST /api/classrooms` ปฏิเสธเฉพาะบัญชีนักศึกษา (403)

เหตุผลของทีม: ต้องมีอีเมลสำหรับทดสอบเว็บและสาธิตให้อาจารย์ดู อีเมลของมหาวิทยาลัยเป็นรหัสนักศึกษา
ซึ่งแต่ละคนมีได้ **บัญชีเดียว** — สาธิตบทบาทผู้สอน + นักศึกษาหลายคนพร้อมกันด้วยอีเมลมหาวิทยาลัยอย่างเดียวไม่ได้
จึงต้องเปิดให้บัญชีนอกโดเมน (เช่น Gmail ทดสอบ) login ได้

ข้อขัดกับ PRD ที่รับรู้ (จาก prd-gap-list GAP-06 / GAP-19):

- FR-AUTH-02 (M) ให้จำกัด hosted domain ต่อ classroom และปฏิเสธอีเมลนอกโดเมนตอน login — ตอนนี้ไม่มีด่านโดเมนที่จุดใด
- PRD ไม่มีแนวคิด "ประเภทบัญชี" — บทบาทมาจาก membership ของห้องเท่านั้น (FR-AUTHZ-01/03)
- กฎเป็น default-allow: บัญชีใดก็ได้ที่ไม่ใช่ตัวเลขล้วน (รวม Gmail ของคนนอกสถาบัน) สร้างห้องและนำเข้ารายชื่อได้
- มหาวิทยาลัยที่ออกอีเมลแบบชื่อ-นามสกุลให้นักศึกษา (เช่นตัวอย่าง `Somchai.A+x@uni.ac.th` ใน AC ของ FR-AUTH-03)
  จะถูกจัดเป็นผู้สอน

## Decision

คงการเปิด login ทุกโดเมนและกฎประเภทบัญชีไว้ **ตลอดช่วงพัฒนาและสาธิต** เพราะเป็นทางเดียวที่ทีมสาธิตหลายบทบาทได้

การป้องกันที่ยังอยู่: สิทธิ์ในห้องทุกอย่างยังตรวจที่ server ผ่าน membership (FR-AUTHZ-01) — บัญชีนอกโดเมน
เห็นได้เฉพาะห้องที่ตัวเองสร้างหรือถูกเพิ่มเข้า ไม่เห็นข้อมูลห้องของคนอื่น

## Consequences

- ระบบ **ไม่ผ่าน FR-AUTH-02** ตามตัวอักษร ต้องแจ้งอาจารย์ตรง ๆ ตอนส่งงาน (บันทึกใน [open-questions.md](../open-questions.md))
- ห้ามใช้ deployment นี้กับข้อมูลนักศึกษาจริงที่ไม่ได้ยินยอมให้ใช้ทดสอบ — คนนอกสถาบันสร้างห้องและนำเข้าอีเมลจริงได้ (§2.4 C2 / PDPA)
- ก่อนใช้งานจริง (ไม่ใช่สาธิต) ให้เลือกอย่างใดอย่างหนึ่ง:
  1. ตั้ง `ALLOWED_EMAIL_DOMAINS=kmitl.ac.th` กลับใน production (staging เปิดทุกโดเมนต่อเพื่อทดสอบได้)
  2. หรือคงทุกโดเมนสำหรับ login แต่ให้สร้างห้องได้เฉพาะ allowlist อีเมลผู้สอนที่เจ้าของระบบกำหนด
     และใช้ `account.py` เป็นตัวช่วยแสดงผลเท่านั้น ไม่ใช่ตัวให้สิทธิ์
