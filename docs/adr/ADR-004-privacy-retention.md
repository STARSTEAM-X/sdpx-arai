# ADR-004: ปิดตัวตนเมื่อพ้นระยะเก็บ (FR-PRIV-02) รวมถึงอีเมลใน audit log

## Status

Accepted — 2026-10-20

ฉบับก่อนหน้า (Proposed) ยกเว้น audit log ไว้ เพราะตีความว่า FR-AUDIT-03 ห้ามแก้ทุกกรณี — ตีความเกินข้อความใน PRD ดู Context

## Date

2026-10-20

## Context

[PRD](../../Sources/SDPX-AI-main/project-ideas/pairwise_evaluation_prd.md):

- **§14.1** อีเมล ชื่อ และ "ผลการประเมิน + ตัวตนผู้ประเมิน" เก็บได้ **2 ปีการศึกษา** · time-on-task 1 ปีการศึกษา — ไม่มีข้อยกเว้นให้ audit log
- **FR-PRIV-02 (M)** หลังพ้นระยะเก็บ MUST แทนตัวตนด้วย pseudonym คงที่ ไม่ใช่ลบทั้งแถว
- **FR-AUDIT-03 (M)** "Audit log MUST เป็น append-only — **ไม่มี API ให้ลบหรือแก้**"

FR-AUDIT-03 ห้ามช่องทางที่ผู้ใช้สั่งลบหรือแก้เหตุการณ์ได้ ไม่ได้ห้ามงานรักษาระยะเก็บที่ FR-PRIV-02 บังคับ
การแทนอีเมลด้วย pseudonym ไม่ลบแถวและไม่เปลี่ยนว่าเกิดอะไร เมื่อไร กับอะไร — ทำได้ทั้งสองข้อพร้อมกัน

audit log มีอีเมลอยู่ 2 ที่: `actor_email` และคีย์ `"email"` ใน `before_state` / `after_state`
(เพิ่ม/ลบสมาชิก — `app/api/members.py`) · ฉบับก่อนหน้าทำให้อีเมลนักศึกษาในคำร้องอุทธรณ์และการเพิ่มสมาชิกค้างอยู่ตลอดไป

## Decision

[app/privacy_job.py](../../backend/app/privacy_job.py) (`python -m app.privacy_job`, ค่าเริ่มต้นดูอย่างเดียว · `--apply` แก้จริง):

- **ตัวตน**: ผู้ใช้ที่ **ทุกห้อง** มีกิจกรรมล่าสุด (กำหนดส่งล่าสุดของงาน หรือวันสร้างห้อง) เก่ากว่า 2 × 365 วัน
  → แทน `email_normalized` / `email_raw` / `display_name` ใน `app_user` ด้วย pseudonym จาก HMAC ของ user id
- **audit log**: แทนอีเมลเดียวกันใน `actor_email` และคีย์ `"email"` ของ before/after ด้วย pseudonym ตัวเดียวกัน
  → อ่านย้อนหลังยังรู้ว่าเหตุการณ์ไหนเป็นของคนเดียวกัน แต่ไม่รู้ว่าเป็นใคร
- **time-on-task**: งานที่ปิดรับเกิน 365 วัน → `comparison.time_on_task_ms = NULL`
- แถวทั้งหมดยังอยู่ · รันซ้ำไม่แปลงซ้ำ · รันด้วยมือหรือ cron ภายนอก — ไม่มี scheduler ในแอป

append-only ยังบังคับที่ database ([023_audit_log_privacy_exception.sql](../../backend/migrations/023_audit_log_privacy_exception.sql)):
trigger ปฏิเสธ DELETE ทุกกรณี และ UPDATE ทุกกรณียกเว้น transaction ที่ตั้ง `paireval.privacy_job = 'on'`
**และ** เปลี่ยนเฉพาะอีเมลเป็นค่า `anon-…@anonymized.invalid` — คอลัมน์อื่นต้องเหมือนเดิมทุกตัว
จึงยังปลอมเหตุการณ์ แก้เวลา หรือเปลี่ยนอีเมลเป็นของคนอื่นไม่ได้ แม้คนที่ต่อ database ได้จะตั้งตัวแปรนั้นเอง
· ไม่มี API ใดแก้ audit log (FR-AUDIT-03)

## Alternatives Considered

1. **ไม่แตะ audit log** (ฉบับ Proposed) — อีเมลนักศึกษาค้างเกินระยะเก็บ ขัด §14.1 / FR-PRIV-02
2. **ปิด trigger ชั่วคราวระหว่างรัน job** — ระหว่างนั้นแก้ได้ทุกคอลัมน์ ข้อยกเว้นกว้างเกินจำเป็น
3. **ลบแถว audit ที่เกินระยะ** — ขัด FR-PRIV-02 "ไม่ใช่ลบทั้งแถว"

## Consequences

- ปีการศึกษานับเป็น 365 วันจากกิจกรรมล่าสุดของห้อง — ระบบไม่มีปฏิทินการศึกษาของมหาวิทยาลัย
- pseudonym ผูกกับ `SESSION_SECRET` — เปลี่ยน secret แล้วผู้ใช้ที่ปิดตัวตนไปแล้วยังคงค่าเดิม (เก็บไว้ในแถวแล้ว) แต่รอบใหม่จะได้รหัสชุดใหม่
- ข้อความอิสระ (`reason`, ข้อความอุทธรณ์) ไม่ถูกสแกนหาอีเมล — ถ้าผู้ใช้พิมพ์อีเมลลงไปเอง ข้อความนั้นยังอยู่
- integration test (`tests/integration/test_privacy_job.py`): ตัวตนใน `app_user` และ audit ถูกแทน · แถวอยู่ครบ ·
  ผู้ใช้ที่ยังมีห้องใหม่ไม่ถูกแตะ · trigger ยังปฏิเสธการแก้คอลัมน์อื่น การเปลี่ยนอีเมลเป็นค่าอื่น การลบ
  และการแทนอีเมลเมื่อไม่ได้ตั้งตัวแปร · ส่วน time-on-task ยังไม่มีเทสต์ที่สร้างคำตอบเก่าจริง
